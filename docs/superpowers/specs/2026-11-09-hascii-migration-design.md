# hascii: миграция прототипа

## Согласованный результат

Переименовать GLYPH/LAB в hascii и мигрировать существующий редактор на Svelte 5 / SvelteKit с TypeScript, сохранив функциональность. Работать в текущей папке. Создать отдельный приватный репозиторий hascii в личном GitHub пользователя. Первый коммит сохраняет текущий рабочий прототип, дальнейшие коммиты выполняют миграцию. Отдельную рабочую копию прототипа не поддерживать.

До изменений исходников зафиксировать исходный проект outputs/ascii-lab, включая оригинальные HTML, CSS и sample.png в dist, package-lock и инструкции запуска. Исключить node_modules, временные файлы, архивы и материалы блога. Полезные проверки из work/verify перенести в отслеживаемые тесты без временных зависимостей. После миграции приложение располагается в корне репозитория, восстановление прототипа возможно через первый коммит. Это размещение — выбор исполнителя.

## Границы

Новые эффекты, аккаунты, публикация сайта и отдельный пакет редактора не входят в миграцию. Существующие сохранённые в браузере палитры и символы переносить не требуется. Сохранение новых палитр и набора символов после миграции должно работать. Возможная интеграция редактора в другой проект — будущая задача; сейчас достаточно отделить вычисления и Worker от UI.

## Функциональный паритет

- Загрузка файлов и drag-and-drop, встроенный пример и пресеты.
- Рабочее разрешение, сохранение пропорций без увеличения исходника, коррекция яркости, контраста и насыщенности.
- Пикселизация, включаемое ограничение палитры, встроенные палитры и импорт Lospec по URL/slug с локальным сохранением.
- Bayer, Floyd–Steinberg, Atkinson, отключение и регулировка силы дизеринга.
- Режимы пикселей, ASCII и фона с ASCII; выбор символов по яркости или яркости и форме.
- Шрифт, размеры, интервалы, наборы символов и произвольные Unicode-символы; существующие ограничения сохраняются.
- Разрешение пустых ячеек и заливка однотонных участков цветом изображения/палитры, а не прозрачностью.
- Цвет однотонного фона, размытие пиксельного фона, независимая непрозрачность фона и символов.
- Превью рядом, сверху вниз и только результат; экспорт PNG в рабочем разрешении.
- Обработка локально в браузере, Worker с объединением частых обновлений; исходные изображения не отправляются на сервер.

Перед переносом составить контрольный список по фактическим исходникам. Скрытые детали поведения сохранять, если они не противоречат этим требованиям. Не исправлять алгоритмы попутно без обоснованного дефекта.

## Стек и интерфейс

Ориентир — E:/CODE/DogsGoToHeaven/DogsGoToHeaven: Node 24, npm, Svelte 5, SvelteKit, Vite, TypeScript, Tailwind CSS, ESLint, Prettier, Steiger, svelte-check, Vitest, Playwright. Использовать совместимые версии из проверенного lockfile ориентира; дополнительные зависимости проверять при реализации. Husky/lint-staged и Conventional Commits адаптировать как локальные инструменты, не копируя правила релизов чужого проекта (выбор исполнителя).

Svelte ASCII UI подключать npm-зависимостью с фиксированной версией 0.2.0, как в Dogs Go to Heaven. Соблюдать публичный API и руководство потребителя. Сохранить расположение интерфейса и бордовую тему; небольшие изменения ради компонентов библиотеки допустимы. Контролы, поля и панели взять из библиотеки; интерактивные превью, палитры и drop zone — композиции приложения. Не копировать внутренности библиотеки и не переопределять её внутренние селекторы. Моноширинный интерфейс; шрифт самого ASCII-рендера остаётся независимой настройкой.

## Архитектура

Соразмерный FSD: тонкие SvelteKit routes, страница playground, необходимые widgets/features/entities/shared с публичными интерфейсами и направленными вниз импортами. Не создавать пустые слои или искусственные сущности. Детальная нарезка — ответственность исполнителя.

Математика обработки — чистые TypeScript-модули, не зависящие от Svelte и DOM интерфейса. Worker владеет обработкой; типизированные сообщения и браузерный контроллер управляют последним запросом, ошибками и освобождением ресурсов. Инициализацию Canvas, Worker и localStorage выполнять только в браузере. Svelte 5 runes для состояния UI; производные значения через derived, эффекты только для синхронизации с внешними API.

SvelteKit adapter-node вместо статического адаптера Dogs Go to Heaven. Серверный маршрут Lospec сохраняет проверку slug, фиксированный upstream и таймаут; пользователь не задаёт произвольный адрес для серверного запроса. Обработка изображений остаётся клиентской. Локальный запуск на 127.0.0.1:4173 — удобный прежний адрес (выбор исполнителя); CI может использовать отдельный свободный порт. Хостинг сейчас не настраивается.

## Проверки и критерии готовности

Линтеры, форматирование, FSD-проверка, проверка типов, тесты и production build проходят локально. GitHub CI выполняет те же проверки на Node 24; без deploy workflow. Ошибки проверок не маскировать отключением правил.

Тесты вычислений покрывают существенное поведение: ограничение палитры/дизеринг, размеры, однотонную заливку и независимые непрозрачности. Сравнить старый и новый движок на одинаковых детерминированных входах, отделяя отличия шрифтов и сглаживания от математических регрессий.

Пользовательские сценарии: загрузка, пресеты, три режима, настройка символов, переключение превью, импорт палитры и ошибки, сохранение PNG. Сетевой импорт в CI проверять управляемыми ответами; отдельно проверить реальный Lospec при доступной сети. Проверить desktop и узкий viewport, клавиатурное управление. Финально открыть приложение пользователю и провести код-ревью.

## GitHub и Codex

Уточнение пользователя: репозиторий в будущем публичный. Сейчас работать только с локальным Git; удалённый репозиторий пользователь подключит после миграции. Это заменяет прежнее решение о приватном репозитории и его создании агентом.

Создание приватного репозитория и отправка коммитов авторизованы пользователем. Текущая проверка gh вернула HTTP 401: перед созданием удалённого репозитория нужна рабочая авторизация; токен не запрашивать в чате. Локальная работа не зависит от GitHub.

Новый чат не нужен. Репозиторий можно добавить в список проектов Codex, продолжая работу здесь. Доступный инструмент перечисляет проекты, но создание/привязку проекта нужно проверить отдельно; не обещать автоматический перенос текущего чата без поддержки инструмента. Это организация рабочего пространства, не условие работоспособности приложения.
